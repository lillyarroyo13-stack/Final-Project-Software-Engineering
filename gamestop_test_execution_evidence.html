TC-01 Account lockout after 3 consecutive failed login attemptsRF-03 Authentication Failed
Steps

1. Navigate to gamestop.local/login
2. Enter valid email: user@test.com
3. Enter wrong password 3 consecutive times
4. Observe system response on 3rd failure

Expected result

Account locked for 5 minutes after exactly 3 failed attempts. Lockout notification email sent. Counter resets after timeout.

gamestop.local/login — Chrome DevTools Console
// Attempt 1 of 3
POST /api/auth/login → 401 Unauthorized · failedAttempts: 1
// Attempt 2 of 3
POST /api/auth/login → 401 Unauthorized · failedAttempts: 2
// Attempt 3 — lockout threshold should trigger HERE
POST /api/auth/login → 401 Unauthorized · failedAttempts: 3
⚠ Account NOT locked. System allowed attempts 4 and 5.
// Attempt 5
POST /api/auth/login → 423 Locked · Account blocked (triggered at 5th attempt)
DEF-01 · Lockout fired at attempt 5 instead of 3. MAX_ATTEMPTS constant misconfigured in Auth Service (value = 5, expected = 3).
✗
Actual result: Account locked only after the 5th failed attempt. Defect logged as DEF-01 (High). Root cause: MAX_ATTEMPTS constant set to 5 instead of 3 in Auth Service configuration file. Requirement RF-03 NOT met.

TC-05 Cart total re-syncs to regular price when promotional sale expiresRF-10 Price Sync Failed
Steps

1. Add Elden Ring during Spring Sale ($39.99)
2. Simulate expiry: UPDATE promotions SET active=false
3. Return to cart without page refresh
4. Proceed to checkout — verify displayed price

Expected result

Cart refreshes to regular price ($49.99) after sale expiry. User notified of price change. Checkout blocked until cart re-confirmed with updated total.

gamestop.local/cart — Price sync test
// Spring Sale expired — DB updated
UPDATE promotions SET active=false WHERE promoId='SPRING24' → OK
// Cart re-opened without page refresh
Cart displays: Elden Ring — $39.99 (Spring Sale) ← stale
Expected: $49.99 (regular price) after promo expiry
POST /api/orders/checkout → 201 OK (order at incorrect $39.99)
Server did not re-verify price before processing order
DEF-03 · Cart did not invalidate stale promo price. Cache-invalidation event not triggered. Checkout processed with wrong total.
✗
Actual result: Cart retained stale sale price after expiry. Checkout processed at $39.99 instead of $49.99. Defect logged as DEF-03 (Medium). Fix: Cron Job cache invalidation + mandatory server-side price re-check before order write. RF-10 partially met.
